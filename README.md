# Work ETA · 剩余时间预测

在输入框下方（composer dock）实时显示「本回合还要多久」。这是 DSH 插件，随回合运行出现、回合结束消失。

Below the message composer, a live reading of how much longer the running turn should take.

## 它怎么算 / How it estimates

预测来自会话日志，不来自猜测模型心情。Host 半部把 `turn/start`、`turn/end`、`todo/write` 折叠成两个数字：

- **预算 `budgetMs`**：当前这份计划的估算总时长。已完成项按实测耗时计价，其余项按「每项实测平均」计价；还没有实测样本时，暂按每项 60 秒的假设。没有 todo 计划时，改用本会话已完成回合的平均时长。
- **已用 `planElapsedMs`**：从计划第一次写入（或从回合开始）到最新日志事件的时长。

客户端用 `剩余 = 预算 − 已用 − 客户端流逝时间` 每秒刷新。因为「已用」本身随每个日志事件增长，而客户端流逝时间在接到新投影时归零，两者之和在任意事件边界都是连续的——工具调用、助手消息都不会冻结或重启读数。

每项实测耗时用滑动平均（最多 4 个样本的权重），单项测量限制在 3 秒 ~ 20 分钟，回合限制在 5 秒 ~ 2 小时，避免挂机把平均值带跑。

## 显示内容 / What you see

- `时钟图标 · 剩 ~2 分 10 秒 · ▬▬▬▭ 2/3`
- **假设态**：只有 0~1 个实测样本时，读数旁多一个「估 / est.」标记，避免把假设冒充实测。
- **收尾态**：计划全部完成时显示「收尾中」；没有计划且没有历史时只显示「已用 X」，不编数字。
- **超预估**：实际用时超过估算时明说「已超预估 X」，而不是假装快完成（真实的剩余工作量无法预知）。
- 进度条与剩余时间同源（都按「已用 / 预算」算），不会出现两个数字各说各话。
- 悬停提示给出依据：样本数、每项实测、正在做哪一项，以及「这是预测，不是承诺」。
- 只在回合运行时渲染；回合结束后不需要清理任何定时器。

## 实现说明 / How it is built

- **Host 半部**（`index.js`）向 `ctx.sessionProjections` 注册 `workEta` 单元：纯函数地从日志折叠出预算与已用，不轮询、不开定时器。
- **Client 半部**（`client.js`）注册到 `conversation.composer.dock` 槽位，每秒重渲染一次；所有数值都是时长，不跨 Host / 浏览器比较绝对时间。
- 文字走 Client locale 服务（中文 / English），样式只用 `--dsw-alias-*` 主题变量，跟随明暗主题。

## 限制 / Limits

- 只在当前回合有工时意义；整回合没有 todo 且没有历史数据时不会给出数字。
- 估算是统计推断，不是模型承诺；一个超长条目、一次重试或长思考都会让它失准。超出预估时插件会如实说明。
- 计划项按文本匹配，改名等同于新条目，会重新计时。
- 计划超过 200 项时降级为只显示已用时间，避免截断造成口径不一致。
- 不改变模型行为，不发额外请求，不写会话事件；关掉插件只是少一个读数。

## 装到哪里 / Where it lives

安装后出现在 **设置 → 插件** 的列表里（标题「剩余时间预测」/ Work ETA），并包含在本 profile 的 `cordis.patch.yml` 中。不需要任何配置项；觉得倒计时打扰的话，直接在插件列表停用即可。
